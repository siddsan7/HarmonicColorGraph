# M6 local UI verification — 2026-09-28

Branch `codex/m6-ui-gates`, commit `d9835d6`. This is a local production
build with mocked browser responses for routes that need the API. It does
not establish the production corpus gate in L03.

## Passed

- Frontend lint, typecheck, production build, and all 31 unit tests.
- Sixteen focused Chromium Playwright tests covering shareable state, graph,
  generation/MIDI, similarity map, and assistant. The mocked three-node graph
  neighborhood laid out and painted in 433 ms. A synthetic 5,000-point map
  painted its hover label 16.3 ms after a real mouse hover.
- Mobile Lighthouse accessibility scored 100 in each of three new clean
  headless Chrome runs. Performance scored 82 and 83 in two of those runs.

## Failed or incomplete

- The third clean Lighthouse run scored 78 for mobile performance, below the
  M6 target of 80. Earlier runs scored 73, 82, 82, and 84. The new runs had
  LCP 3.32–3.76 seconds and total blocking time 298–457 ms. The gate is
  inconsistent and remains open; these measurements do not establish a
  repeatable pass.
- Lighthouse wrote complete JSON reports with no `runtimeError` in each run,
  but its Windows CLI exited 1 because Chrome's temporary profile could not
  be removed (`EPERM`). This cleanup failure is separate from the scores.
- The local FastAPI server was unavailable during the UI runs, so `/health`
  proxy requests logged connection refusals. Playwright API responses were
  mocked. Real corpus map/network load, Safari/iOS audio, and production
  browser acceptance remain unverified.

The detailed local Lighthouse JSON files are under `.agent-logs/` and are
excluded from Git. The score variance is associated with main-thread
blocking, but these runs do not isolate a safe code change. Audio imports
are a possible contributor; changing their load path needs a separate
Safari gesture and playback regression check.
