# ADR-007 — Storage budget

**Status:** Accepted (roadmap v2)

**Context:** The June 2026 full-provenance corpus seed hit
Supabase's free-plan limits (500 MB database quota, 1 GB disk)
and failed with `DiskFull` mid-transaction, rolling back and
leaving the project temporarily read-only. Nothing enforced a
size budget before that load was attempted.

**Decision:** Target ≤ 300 MB for the `hcg` schema including
indexes (worksheet in
`feature-specs/v2-implementation-plan.md` Appendix B), enforced
by measuring `scripts/db_size.sql` after every load (F24) and as
a check gate (G5) on any feature that touches the database. The
overflow playbook, in order: tighten n-gram pruning thresholds
(`pipeline/params.yaml`) → drop low-support `decade`/order-3
contexts → move `ngram_histories` to a zstd-compressed artifact
in Supabase Storage, loaded per warm instance → upgrade to
Supabase Pro (requires Siddharth's approval — costs money).

**Consequences:** Aggregation stages must prune aggressively
(supported by measured corpus statistics in
`docs/roadmap-v2.md` §2.3) rather than storing every observed
n-gram or pattern; every schema-touching feature must report a
size number, not just "it loaded."

**Revisit trigger:** A load exceeds budget even after the first
two playbook steps, or the product genuinely needs Supabase Pro
for other reasons (compute, backups) and the cost is approved
anyway.
