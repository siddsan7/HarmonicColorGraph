# ADR-001 — Offline build, online serve

**Status:** Accepted (roadmap v2)

**Context:** The corpus pass, aggregation, embeddings, and color
percentile computation over ~680k songs are heavy, slow, and
only need to run when the corpus or algorithms change — not on
every request. The API runs on Vercel serverless functions with
cold starts and bundle-size limits.

**Decision:** Nothing heavy runs in a request. A Python offline
pipeline (`backend/pipeline/`, extras `[pipeline]`/`[ml]` only:
Polars, gensim, scikit-learn, scipy, music21) produces versioned,
hashed Parquet artifacts plus a manifest. A separate loader COPYs
them into Supabase. The FastAPI service (`backend/app/`) only
ever reads compact derived tables through runtime dependencies
(fastapi, pydantic, sqlalchemy, psycopg, numpy) and never imports
the pipeline package.

**Consequences:** Fast, small, serverless-safe API; reproducible,
re-runnable corpus builds; an extra deploy step (load + activate
a version) whenever the corpus changes; pipeline code must be
excluded from the Vercel function bundle (`vercel.json`
`excludeFiles`).

**Revisit trigger:** If a feature genuinely needs sub-second
access to raw per-song data that can't be precomputed, or if the
pipeline needs to run continuously rather than on demand.
