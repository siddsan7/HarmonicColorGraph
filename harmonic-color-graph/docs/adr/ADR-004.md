# ADR-004 — music21 is an oracle, not a runtime dependency

**Status:** Accepted (roadmap v2)

**Context:** Phase 1 listed `music21` as a backend dependency but
never actually used it for analysis; it is a large library
(with its own corpus data) that would bloat the Vercel function
bundle and cold-start time if it were imported at request time.

**Decision:** Analysis v2 (spelling, key finding, Roman numerals,
relationships) is implemented in-house in
`backend/app/theory/`: fast, small, and fully unit-tested.
`music21` is used only in a dev-only script
(`backend/pipeline/oracle_music21.py`) to cross-check the gold
sets (`data/gold/keys.jsonl`, `data/gold/roman.jsonl`) and is
declared only in the `oracle` extra, never in
`[project.dependencies]`.

**Consequences:** The runtime API never pays music21's import
cost or bundle size; in-house theory code owns full
responsibility for correctness, backed by gold-set agreement
metrics (`docs/eval/keys.md`, `docs/eval/roman.md`) rather than
borrowed correctness from a third-party library.

**Revisit trigger:** If in-house analysis cannot reach the
accuracy gates in `feature-specs/v2-implementation-plan.md`
(F11/F12) even after tuning, reconsider using music21 as a
fallback for specific hard cases (still offline, never in the
request path).
