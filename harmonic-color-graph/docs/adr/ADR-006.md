# ADR-006 — LLM is an interface, never an oracle

**Status:** Accepted (roadmap v2)

**Context:** The product's credibility depends on never
presenting an LLM's guess as musical fact — an invented "this
song uses this progression" or an absolute emotional claim would
undermine the whole "harmonic intelligence engine" positioning
(`context/project-overview.md`, `context/ai-workflow-rules.md`).

**Decision:** The AI assistant is a LangGraph workflow inside the
FastAPI service, using Claude through `langchain-anthropic`. It
may only call safe, typed internal tools (`backend/app/ai/tools.py`)
that wrap existing deterministic/statistical services, never
arbitrary SQL or free-form retrieval. All tool outputs and the
final response are Pydantic-validated structured data. A
validator node (F72) rejects any chord not produced by a tool and
any claim without a cited `fact_id` from `hcg.facts`; on failure
the workflow retries once, then falls back to a deterministic
template response with no LLM content.

**Consequences:** Every LLM-facing capability needs a
tool + schema + fact IDs before the assistant can use it, which
gates AI work behind the underlying feature actually existing;
adversarial prompts ("invent a progression", "ignore your tools")
must be caught by the validator rather than by hoping the model
declines.

**Revisit trigger:** None expected before v1.0; this is a
foundational product-trust decision, not a performance one.
